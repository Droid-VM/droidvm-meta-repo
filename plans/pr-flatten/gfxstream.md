## gfxstream — base 7e9d595b0 (aosp/android16-qpr2-release) .. 6cfa0fbc2 (wip/3d-accel)  95 original commits, 61 net files (+7610/-1136)

Repo: `/root/gitrs/DroidVM/DroidVM_3daccel_gfxstream/crosvm_build/hardware/google/gfxstream`.
Everything here is the gfxstream host (crosvm-side) library; there is no guest code. All of it is
bucket **X** except the licensing files (**L**). Twelve leading commits are lateautumn233's
(**other-author**, kept). One commit from the org's older `droidvm/wip-3d-accel` (d3d42c144
"host-visible arena config scaffold") is **not** in `wip/3d-accel` — intentionally dropped, it was the
first scaffold of what became 4c8f0a838 → a7765887b (see "Nets to zero").

Bucket decision for the host-visible / pool / RingBlob work: **X, ordered first among the X commits and
tagged "X (G-interface)"**. Reason: only the gfxstream route executes this code (venus/drm2kgsl go
through virglrenderer), so by the PREAMBLE's definition it is not "shared by ≥2 routes"; but it is the
gfxstream half of the crosvm G-bucket pool ABI — `struct stream_renderer_handle` grows
`_pad_pool`/`pool_offset`, new `STREAM_HANDLE_TYPE_MEM_POOL 0x7`, custom init params 2048/2049
(prepare/release blob-backing callbacks), the `GFXSTREAM_POOL_FD/_FD_OFFSET/_GPA/_SIZE/_HOST_MB/
_BLOB_MAX_KB`, `GFXSTREAM_VRAM_BUDGET_MB` env contract, and the capset `guestAllocOffsetMb/SizeMb`
fields (plus `hasSetMetadataCommand` for guest layout parity). It must land in lockstep with (and be
cross-referenced from) crosvm's G pool/udmabuf/blob-backing commits, or the FFI struct sizes disagree.
